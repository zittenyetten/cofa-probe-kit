# 요구사항에서 검증 근거까지

과제에 맞는 작은 결과를 만들고, 실제로 확인한 범위를 설명한다. 공식 평가 기준이나 자동 응시 도구가 아니다. 별도 API·MCP·설치는 필요하지 않다. 현재 환경의 권한과 최신 안내 안에서만 실행한다.

구체적인 질문 순서나 QA 진행 방법이 필요할 때만 [인터뷰·QA 방법 안내](../../references/interview-qa-methods.md)의 해당 절을 읽는다. 기존 원칙의 상세 참고이며 추가 스킬·OOO 실행 절차가 아니다.

## 토큰 절약 쉬운 방식

**중복 읽기·설명은 줄이고, 필요한 작업·검증은 유지한다.** 토큰 절약만 요청받았다면 이 절만 적용하고 나머지 절차를 새로 시작하지 않는다.

1. **필요한 자료만 읽기.** 실제 지시서의 필수 조건·예외는 빠짐없이 확인하고, 참고자료는 관련 절만 읽는다. 큰 데이터·로그는 도구로 필요한 전체 범위를 처리하되 채팅에는 요약과 확인에 필요한 부분만 출력한다. 일부 행만 보고 전체를 검증했다고 하지 않는다.
2. **같은 내용 반복하지 않기.** 이미 확인한 자료·답을 활용하고 전체 계획·설명을 매번 다시 쓰지 않는다. 자료가 바뀌었거나 맥락이 빠졌거나 근거가 불명확하면 필요한 원문을 다시 확인한다.
3. **결과와 바뀐 점 위주로 말하기.** 진행 중에는 변경·막힘·다음 행동을, 완료 때는 결과 위치·검증 근거·한계를 짧게 알린다. 과제가 요구한 설명·항목과 오류 원인은 생략하지 않는다.
4. **끝난 검사를 이유 없이 반복하지 않기.** 필수 검증 후 변경·실패·미해결이 없으면 마친다. 수정한 부분의 재검사와 요구된 반복 측정·재현 확인은 수행한다.
5. **절약용 절차를 더 만들지 않기.** 이 방식 때문에 새 세션·역할·기록 파일·설정·측정기를 추가하지 않는다. 기존 작업을 이어가며, 측정 없이 토큰 절감률·비용·점수 효과를 단정하지 않는다.

응시용 모델은 **Sol 6.1·Terra 5.6·Luna 6·Sol 6.0만 사용**한다. **Astra·목록 밖 모델로의 대체와 제공 Codex·도구·환경 업데이트·자동 갱신은 금지**한다. 허용 모델로 잘 작동하면 현재 설정을 유지한다. 선택을 묻거나 변경 이유가 생긴 경우만 [쉬운 선택표](../../references/prompt-skill-template-guide.md#6-모델과-추론-수준-쉽게-고르기)를 참고한다. 허용 모델을 사용할 수 없으면 운영 문의로 확인하며 임의 대체·업데이트로 해결하지 않는다. 실제 설정 확인 없이 모델·추론을 바꿨다고 하지 않는다.

## 입력을 읽고 필요한 것만 묻기

- 현재 과제 안내·원자료·기존 결과·받은 답변을 읽는다. 없는 파일이나 접근할 수 없는 자료를 읽었다고 하지 않는다.
- 외부 검색이 없으면 제공 자료·로컬 파일·실제 담당자 답변으로 진행한다. 접근할 수 없는 출처를 읽었다고 하거나 검색 결과를 만들지 않는다. 기존 지식은 설명을 보조하되 미확인 업무 기준·수치를 확정하지 않는다. 이미 있는 도구와 허용된 내부 서비스를 쓰고, 외부 다운로드가 필요한 방법을 기본으로 삼지 않는다.
- 목표, 필수 산출물, 핵심 처리 규칙, 제한을 짧게 정리한다. **지시서 요구 / 담당자 확인 / AI 추가 제안 / 사용자의 채택·제외 결정**을 근거 위치와 함께 구분한다. 상태는 확인·가정/제안·미확인·충돌로 표시하며, AI 제안을 자동으로 필수 요구에 넣지 않는다. 필요할 때만 간단한 표나 ID를 쓴다.
- 답에 따라 결과가 달라지는 공백부터 질문한다. 담당자에게는 실제 사용자·입력·업무 상황·판단 기준·실패 시 허용 결과를 묻고, 그 답이 어떤 구현·분석 결정을 바꾸는지 연결한다. 이미 자료에 있는 답을 다시 묻지 않는다. 질문은 사용자가 전달할 수 있게 작성하고 담당자 답을 대신 지어내지 않는다.
- 필수 결과를 막거나 잘못 가정했을 때 재작업이 큰 질문을 우선한다. 기본은 한 질문이며 같은 결정에 필요한 짧은 항목은 묶을 수 있다. 열린 질문으로 업무 기준을 듣고, 답이 모호하면 실제 사례·경계로 좁힌다. 선택지를 쓸 때는 다른 기준도 가능하게 열어 두며 특정 답을 유도하지 않는다.
- 실제 답이 오면 답한 범위만 확인 상태로 갱신하고, 자기 해석·부분 답변의 미응답 항목은 구분한다. '확인'은 현재 근거를 이해했다는 뜻이지 실제 데이터·구현이 검증됐다는 뜻이 아니다. 질문 조언은 바뀐 이해, 다음 질문과 이유, 작업·검증 영향만 짧게 제시한다.
- 출처가 충돌하면 양쪽 조건과 결과에 미치는 차이를 보여준다. 나중에 발견한 문장이라는 이유만으로 우선하지 않는다. 권한 있는 담당자의 명시적 정정은 이전 조건을 대체한다고 기록한다.
- 담당자도 모르면 필요할 때 다른 자료·담당자·사례로 확인할 경로를 한 번 좁혀 묻는다. 경로가 없으면 같은 질문을 반복하지 않고 영향받는 결정만 보류한다. 그 조건 없이도 확인할 수 있는 중요한 업무 질문과 독립적인 작업은 계속한다. 시간이 부족하다는 이유로 미확인을 승인된 가정으로 바꾸지 않는다.
- 필수 조건과 확인 방법이 충분하면 질문을 끝내고 작업한다. 모든 단계에서 반복 승인을 받거나 정해진 질문 개수를 채우지 않는다.

## 작게 실행하고 검증하기

1. 필수 요구마다 **작업 → 확인 대상·방법 → 관찰 가능한 통과 기준**을 연결한다. 계획만 요청받았다면 실행하지 않고 이 연결까지만 제공한다.
2. 실행을 요청받았다면 허용된 도구로 필수 결과부터 만든다. 과제가 지정한 파일명·형식·범위를 지키고 원본 입력은 보존한다. 불필요한 대시보드·서비스·패키지는 추가하지 않는다.
3. 업무 규칙으로 예상 결과를 정하고 실제 결과와 대조한다. 필요한 경우 원자료의 작은 사례를 직접 계산하거나 구현과 다른 방법으로 확인한다. 같은 코드의 재실행이나 AI의 동의만을 독립 검증이라고 부르지 않는다.
4. 데이터 과제는 해당하는 검사만 선택한다: 행·키별 포함/제외, 누락·중복, 결합에 따른 행 증가, 단위·분모, 경계값, 합계. 합계가 맞는다는 이유로 행별 대응까지 맞다고 하지 않는다. 화면·파일 과제라면 실제 열기·실행·요구 기능을 확인한다. 대체값·추정값·임시 결과가 있다면 내부 상태뿐 아니라 사용자가 보는 화면·출력에서도 실제 결과와 구별되는지 확인한다.
5. 빈 값·알 수 없는 상태를 자동으로 0, 정상, 제외, 반대 범주에 넣지 않는다. 명시된 정책을 적용하거나 해당 결과를 미확인으로 남긴다. 숫자·허용 오차·업무 정책을 임의로 확정하지 않는다.
6. 과제에 해당하는 정상·실패·대체 결과·재시도 경로를 기대 결과와 실제 관측으로 대조한다. 재시도가 있다면 복구 후 표시와 중복 처리·누락 여부까지 확인하되, 필요 없는 복구 기능을 추가하지 않는다. 오류 수정 뒤 실패했던 사례와 관련 요구를 다시 검사한다. 검사 상태는 **미실행 / 통과 / 실패 / 보류**로 구분하고, 확인하지 못한 경로를 없거나 정상이라고 단정하지 않는다.
7. 조건이나 입력이 바뀌면 영향받는 결과·검증 기준을 갱신한다. 이전 조건에서의 통과를 재사용하지 않는다. 필요한 이전 기록은 보존하되 현재 유효한 결과를 분명히 표시한다.

## 짧은 작업 기록

시작 요청에 WORKLOG 기록이 포함되거나 사용자가 요청하면 [빈 양식](../../templates/WORKLOG.template.md)을 처음에만 참고한다. 실제 `WORKLOG.md`는 **공개 참고자료 폴더 밖의 해당 과제 작업 공간**에 한 개로 유지한다. 과제가 정한 위치를 확인하고 기존 기록을 읽어 이어 쓰며, 위치가 불명확하면 확인한다. 공개 양식·문서·열람 자료에 실제 기록을 넣거나 외부 전송·push하지 않는다.

현재 목표·진행·막힘·다음 행동, 필수 요구별 **미시작 / 진행 중 / 결과 생성 / 검증 완료 / 보류**와 근거를 남긴다. 생성과 검증을 구분하고, 중요한 질문·프롬프트의 목적/답 요약, 사용자의 실제 결정/밝힌 이유, 검사 방법/수행자/실제 관측/미검증/수정 후 재확인만 연결한다. 제안을 사용자 결정으로 바꾸거나 말하지 않은 이유를 추측하지 않는다.

범위 확정·첫 결과 완성·중요 수정·제출 직전에 바뀐 부분만 짧게 갱신한다. 매 대화 전문이나 별도 보고서를 반복 생성하지 않는다. 조건 변경 시 관련 상태·검사를 갱신한다. **‘진행 점검’** 요청에는 기록과 최신 관측을 대조해 상태·누락·막힘·다음 행동·검증 범위를 총 5줄 안으로 답한다. 파일을 갱신하지 못했으면 그 사실을 밝힌다. AI 금지 단계에서는 기록·답변을 계속하지 않으며 기록 재열람 허가를 추정하지 않는다.

## 작업을 마칠 때

결과 위치, 누가 내린 선택인지와 그 이유, 실제 검증 방법·결과, 남은 불확실성을 짧게 보고한다. 코드에 분기가 있거나 근거 링크가 보이는 것과 실제 경로를 실행한 것을 구분한다. 과제에서 요구한 문서가 있다면 거기에 모으고 같은 내용을 여러 파일로 반복하지 않는다.

같은 허용 환경의 다른 작업 AI 세션으로 넘길 때만, 원문·입력 위치, 실제 정의·수치·기간·예외·필수 출력, 미확인과 보류 범위, 검증 방법·현재 상태를 인계 본문에 담는다. '위 내용대로'나 요구 ID만으로 조건을 대신하지 않는다. 같은 세션에서는 기존 기록을 이어 쓰면 된다. 인터뷰 질문·인계 요청 예시는 [RUNBOOK의 실전 인터뷰](../../RUNBOOK.md#실전-업무-인터뷰-루프)를 참고한다.

사용자가 설명 연습을 요청하면 본인이 먼저 선택 이유와 검증 근거를 설명하게 하고 실제 작업과 대조한다. AI가 수행한 일을 사용자가 직접 수행한 것으로 바꾸지 않는다. AI 금지 단계의 답변을 대신 작성하지 않는다.

Cofa의 평가 관점이나 이 절차의 배경을 묻는 경우에만 [공개 인터뷰 핵심](references/cofa-core.md)을 읽는다. 인터뷰의 사례·모델·배점을 현재 과제의 요구나 규정으로 옮기지 않는다.
